# Iteration 08 — 档案揭示修复 + 锚点量测可信化

环境：`npm run build` exit 0 · `tsc` 0 错误 · `next start -p 3005` · 1440×900 @dpr1 / SwiftShader

## 一、已修：精选网格「挂载时不在视口内的卡片永久隐藏」
根因（运行时量出来的，不是猜的）：`FeaturedWorkGrid` 的揭示 ticker 会**在弹簧全部静止时自行终止**，但 `startTicker` 返回的 stop 句柄**仍留在 `stopReveal.current` 里（非空）**，于是 `wake()` 的 `if (!stopReveal.current)` 守卫永远为假 —— **滚动唤醒彻底失效，再也不会重启**。

实测证据（修复前）：滚动到 1930 后，CyberBrokers / The Examination 的 `cropTop = -412`（早已滚过），`scrollProgress` 理应返回 1，但内联 `opacity` 仍是 **0**、cropper 仍 `scale(0.8)`；而挂载时就在视口内的前 4 张卡走 `settle()` 分支，正常显示。**只有走 ticker 分支的卡全被冻死。**

修法：ticker 自然结束时把句柄置空，让后续 `scroll` 能重新唤醒。

## 二、`work__50pct` 的 92.63 是相位偏移，不是内容缺失（已证）
目视两侧同一位置：我们的档案行**高度还原** —— 同样的行序、衬线标题、`View project` 描边胶囊、分隔横线、年份/客户列。差异来自原站该处顶部有一条**黑色带**（精选网格末尾），我们那里是空白，加上累计纵向偏移。

用锚点工具量化后确认：`/work` 前两个锚点 delta=**0**，之后 **+24、+48** 逐行递增 —— 我们的精选卡每行比原站高约 24px，累计造成 50% 处错位。**属可修的度量/高度问题，不是内容缺陷。**

## 三、锚点工具修正（此前 MISSING 全不可信）
`compare-anchors.mjs` 原来按原始文本精确匹配，而标题常含**重复两遍**的文字（动画层 + 静态层），两侧是否带分隔空格还不一样（原站 `"National Geographic National Geographic"` vs 我们 `"National GeographicNational Geographic"`），导致大量假 MISSING。
已加 `normKey()`：折叠空白、去掉重复的一半、小写化后再匹配；同时取消"先截断到 MAX_ANCHORS 再匹配"造成的漏配。
